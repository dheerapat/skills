def digest_for(conn, today: date) -> tuple[str, str]:
    yesterday = today - timedelta(days=1)
    with conn.cursor() as cur:
        return render(yesterday, count_signups(cur, yesterday))

def main() -> None:                      # wiring only: driver, DSN, clock, mail
    import psycopg2
    with closing(psycopg2.connect(os.environ["PG_DSN"])) as conn:
        subject, body = digest_for(conn, date.today())
    notify.send(RECIPIENT, subject, body)

Design report (what a SOLID review would ask):

- **Gate:** only **D** matched — `psycopg2.connect` + `date.today()` + SMTP are I/O; a naive `main()` makes the count untestable without a live DB.
- **Seam:** rung 1, *parameters*. Connection and clock passed in; concrete things constructed at the edge. Zero new types, zero classes.
- **S:** three reasons to change split by function — `count_signups` (SQL), `render` (wording), `main` (wiring). One file is correct for a script this size.
- **O / L / I:** nothing applies — no variant chain, no subtypes, no fat interface.
- **Not done (deliberate):** no `Mailer`/`Database` Protocol, no factory, no registry. `notify.send` is the repo's single mail implementation with one caller — abstracting it is the unused-indirection mistake. Revisit when a second sender actually lands.

Cron: `15 6 * * * cd /srv/corp && /usr/bin/env python3 /srv/corp/daily_digest.py`. No `try/except` on purpose — a traceback on stderr makes cron mail the failure instead of the digest silently vanishing.
